# MFOX v1.4.16 — voting rebuilt from scratch

Scope: voting only.

## Why the previous implementation was unstable

The public candidate cards still used Shiny-bound action buttons and reactive vote outputs. A vote therefore entered Shiny's output invalidation cycle even though most of the card had been made static. Depending on the browser/deployment, this could still produce a shaded/recalculating surface or detach controls during the click lifecycle.

## New architecture

- Candidate vote controls are plain HTML buttons with `type="button"`.
- A capture-phase browser handler prevents default/form/navigation behavior and sends a single `candidate_vote_event`.
- The server uses one observer for all candidates.
- The entire observer is error-contained; failures are returned to the clicked card.
- The public candidate cards and summary are rendered once and have no reactive dependency on vote state.
- The server replies via `candidate_vote_ack`; only text/counts/button state in the clicked card are changed in the DOM.
- The two buttons alone are disabled while awaiting acknowledgement; there is no page-level busy state.
- An 8-second client timeout re-enables the controls if the server does not answer.
- Disk persistence is best-effort and is separated from in-session voting.
- Voting no longer depends on `session$token`.

Scientific data and all other feature areas are unchanged from v1.4.15.
